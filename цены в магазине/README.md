# METRO: история обычных цен

Python + Selenium + pandas. Запуск через `main.py`. История хранится в CSV, база данных не используется. Работать с сайтом нужно без VPN.

## Установка

Откройте терминал в этой папке. Установите Python 3.11 или новее и Google Chrome.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Selenium автоматически подбирает драйвер браузера. Если его загрузка недоступна, можно указать совместимый драйвер через `--driver C:\путь\chromedriver.exe`. Для Edge используйте `--browser edge`.

## Первый пробный запуск

```powershell
.\.venv\Scripts\python.exe main.py --probe
```

В открывшемся браузере выберите Москву и конкретный торговый центр. При необходимости самостоятельно подтвердите возраст для просмотра алкоголя. Когда каталог загрузится, вернитесь в терминал и нажмите Enter. Первый запуск обходит до трёх категорий по одной странице. В `output/debug` сохраняются HTML и снимки страниц для проверки селекторов.

Браузер не ждёт загрузки всех баннеров и аналитики: парсер отдельно ожидает адрес магазина и карточки товаров. Если после Enter каталог ещё загружается, увеличьте ожидание: `python main.py --probe --timeout 90`.

**Живой пробный сбор подтверждён 5 октября 2026 года:** из разделов алкоголя, мяса и бакалеи получено 110 товаров с обычной ценой торгового центра на Ленинградском шоссе, 71Г. Это проверка нескольких страниц, не подтверждение полного обхода каталога. Нулевое число подтверждённых обычных цен считается ошибкой и требует проверки сохранённого HTML, а не подстановки онлайн-цен.

## Полный еженедельный запуск

**Текущий режим по умолчанию — фиксированная корзина 500 товаров.** Первый `python main.py` выбирает 360 продуктов, 90 напитков (включая алкоголь) и 50 бытовых расходников и средств гигиены. Товары с подтверждённой обычной ценой сохраняются в `basket.csv`; последующие запуски проверяют только эти SKU по ссылкам карточек, в одном браузере Selenium с сохранённым профилем магазина. Корзина не меняется автоматически при исчезновении товаров. Ошибки проверки обозначаются «Не удалось проверить», без подстановки старой цены.

Создание корзины сохраняется после каждой страницы в `basket_progress.json` и автоматически продолжается после перезапуска. Первая подготовка может занимать больше времени, чем еженедельная проверка. 10 минут — ориентир, а не измеренная гарантия.

Проверенный профиль для корзины: `python main.py --yes --profile browser_profile/basket`. Для старого режима полного каталога укажите `--full`. Не используйте команду продолжения старого полного каталога, если нужна корзина.

```powershell
.\.venv\Scripts\python.exe main.py
```

Используйте один и тот же торговый центр для сопоставимых замеров. Выбор сохраняется в отдельном профиле браузера `browser_profile`. Не запускайте две копии одновременно. После успешной настройки можно запускать `python main.py --yes`, а без окна — `python main.py --yes --headless`.

Если Chrome сообщает `DevToolsActivePort`, закройте окно предыдущего запуска парсера или используйте другой профиль: `python main.py --probe --profile browser_profile/test`. Настройки региона для отдельного профиля выбираются заново.

Парсер ищет ссылки категорий в меню и на посещённых страницах, обходит ссылки пагинации, удаляет дубликаты SKU. Количество найденных категорий и состояние каждой страницы записываются в отчёт. Покрытие относится к обнаруженному веб-каталогу: оно не доказывает наличие на сайте всего ассортимента физических магазинов.

## Файлы

- `output/prices_ДАТА_ВРЕМЯ.csv` — отдельный снимок: товар, категория, адрес магазина, обычная цена, единица цены, упаковка, дата, наличие и ссылка.
- `output/prices_ДАТА_ВРЕМЯ.json` — состояние сбора, ошибки, категории, страницы и число товаров с подтверждённой ценой.
- `output/changes_ДАТА_ВРЕМЯ.csv` — сравнение с последним полным замером того же магазина. Пробные и частичные замеры не становятся базой сравнения.
- `output/debug` — диагностика проблем и пробного запуска.

Новые запуски также сохраняют наблюдения после каждой страницы в `output/debug/ИДЕНТИФИКАТОР/checkpoint.csv`. Это технический журнал с английскими названиями полей и возможными повторными SKU при уточнении категории, а не итоговый недельный снимок. Итоговый CSV сохраняется при завершении или остановке через Ctrl+C.

Для продолжения прерванного сбора используйте `python main.py --yes --profile browser_profile/verification --resume output/debug/ИДЕНТИФИКАТОР`. Можно также передать итоговый CSV неполного запуска. Завершённые категории пропускаются, незавершённые собираются заново. Это продолжение прежнего замера; даты товаров сохраняются. Для следующей недели запускайте без `--resume`.

CSV имеют одинаковые русские заголовки и UTF-8 с BOM. Идентификаторы при импорте в MongoDB нужно читать как строки, цены — как числа, даты — как даты. Пустая цена означает отсутствие подтверждённой цены, а не ноль.

Для недельной истории корзины выбирайте CSV с `Тип замера = Корзина 500` и `Статус замера = Завершён`. Сравниваются только замеры того же магазина с тем же набором SKU. Полный каталог и корзина не смешиваются. Пробные и неполные запуски полезны для диагностики, но не являются самостоятельными недельными замерами.

Обычная цена берётся из явно обозначенного блока торгового центра за одну продажную единицу. При акции используется зачёркнутая цена этого блока. Если блок неоднозначен, содержит только оптовую цену, цену по карте или обычная цена не подтверждена, числовое поле остаётся пустым, исходный текст сохраняется. Онлайн-цены не подставляются.

Наличие также определяется по блоку торгового центра. Статус онлайн-заказа не доказывает наличие в магазине. «Нет в наличии» используется при явном сообщении источника; «Не найден в каталоге» — если товар исчез после успешного обхода его категории; при ошибках — «Не удалось проверить».

Изменения рассчитываются для одной пары магазин + SKU, при совпадающих упаковке и единице цены. Переупаковка не считается изменением цены той же упаковки. Собирать несколько магазинов можно отдельными запусками, выбрав нужную точку: цены магазинов не усредняются автоматически.

Коды завершения: 0 — успешный сбор или пробный запуск; 1 — ошибка; 2 — неполный полный запуск; 130 — остановка пользователем. Полученные до ошибки карточки сохраняются.

## Локальная проверка

```powershell
python -m unittest discover -s tests -v
```

Проверяются отделение цены магазина от онлайн-цены, исключение оптовых и карточных цен, сравнение замеров, исчезновение товара при ошибках, изменение упаковки и сохранение идентификаторов.
## Режим для September.pdf — 5 октября 2026

Новая команда для сдачи: `python main.py --inflation --collect`. Равнозначная команда: `python inflation.py --collect`. Она работает с отдельной фиксированной **продуктовой** корзиной: один товар на группу, в одном московском METRO. Первый сбор выбирает максимально доступное число групп в бюджете; следующие проверяют те же SKU по ссылкам, без автоматической замены.

Ссылки, разделы, группы и количество продажных единиц хранятся в `inflation_basket.toml`. Бюджет — четверть федерального МРОТ 2026 года (27 093 ₽), то есть 6 773,25 ₽ с допуском ±5%: 6 434,59–7 111,91 ₽. Проверяется сумма цен выбранных упаковок либо 1 кг/л для весовых товаров. Цена для анализа отдельно хранится в руб/кг или руб/л. Приблизительные/неизвестные массы и неоднозначные мультиупаковки не пересчитываются по догадке. Основание МРОТ сохранено ссылкой в TOML; для нового года требуется обновить величину.

Снимки и журнал находятся в `output/inflation`; `weekly_prices.csv` — матрица недельных цен, `latest.json` — полнота и проверка бюджета. Повторные проверки в той же календарной неделе не добавляют фиктивную новую неделю. Исходные даты наблюдений сохраняются. Ошибки обозначаются явно, старая цена не подставляется. Если цена выросла и корзина вышла за исходный бюджет, это отмечается, а состав остаётся фиксированным.

Запускайте сбор вручную раз в неделю. После замера 5 октября следующий — **12 октября 2026**:

```powershell
.\.venv\Scripts\python.exe main.py --inflation --collect --profile browser_profile/verification
```

Обычный `python main.py` по-прежнему работает с корзиной 500. Её создание теперь восполняет дефицит товаров другими товарами той же группы (360 продуктов / 90 напитков / 50 бытовых товаров) и использует реальные ссылки дочерних категорий вместо повторяющихся родительских страниц. Повторный сбор сохраняет профиль магазина. Нормализованные цены добавлены и в новые обычные CSV. Исправлены ошибки классификации ингредиентов: лапша с говядиной не становится говядиной, сыр с креветкой остаётся сыром, хлеб на закваске не считается квасом, сельдерей — рыбой, продукт «без сахара» — сахаром.
