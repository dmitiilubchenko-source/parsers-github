# Аэропорты

## Сбор данных

Из корня проекта запустите:

```powershell
.\.venv\Scripts\python.exe .\scripts\html_airports_scraper.py
```

Парсер продолжает ранее завершённый сбор и сохраняет исходные записи в `outputs/html/airports_html.json`, а состояние обработки — в `outputs/html/html_scrape_status.csv`. HTML-кэш находится в `cache/html/`. Быстрая проверка на десяти ICAO: `--limit 10`. Для списка других параметров: `--help`.

Код разделён на модули в `scripts/airport_parser/`: `config.py` (настройки и список ICAO), `local_data.py` (резервные локальные CSV), `downloader.py` (загрузка и кэш), `html_parser.py` (разбор страниц), `output.py` (сохранение), `pipeline.py` (обработка аэропорта), `cli.py` (основной цикл). `scripts/html_airports_scraper.py` — точка входа.

## Фильтрация готовых данных

Отредактируйте `filter_config.json`, затем запустите **отдельную команду**:

```powershell
python .\sort_airports.py
```

В `filter_config.json` можно менять:

- `airport_types` — допустимые типы аэропортов; пустой список оставляет все типы;
- `require_complete` — `true` оставляет записи, у которых заполнены все поля из списка `fields`, включая значения внутри вложенных списков и объектов. `null`, пустые строки, списки и объекты считаются незаполненными; `0` и `false` допустимы. Тип объекта на эту проверку не влияет;
- `include_icao` — список ICAO для включения; пустой список означает все аэропорты;
- `exclude_icao` — список исключений; исключение имеет приоритет;
- `fields` — поля выходных файлов в нужном порядке;
- `formats` — любые из `json`, `csv`, `ndjson`.

Пример ручного выбора: `"include_icao": ["UUEE", "UUDD"]`, `"exclude_icao": ["UUDD"]` даст только UUEE, если он удовлетворяет остальным фильтрам.

Поля `id`, `ident`, `gps_code`, `local_code`, `scheduled_service`, `continent`, `municipality`, `location`, `coordinates`, `field_elevation`, `home_link`, `members`, `type` берутся из вложенного `facility_fields`. Они могут быть пустыми (`null`), если источник их не содержал. `routes` добавляется по ICAO из `data/airline_routes.json`; если аэропорта в этом файле нет, выводится пустой список. Высота в `elevation_ft` и `elevation_m` берётся из основных полей записи; `field_elevation` — исходный текст страницы.

Типы объектов сейчас не ограничены. Проверка полноты отключена: неполные записи сохраняются с пустыми значениями. При включении проверки выводится число записей с незаполненными значениями каждого выбранного поля. `type` при отсутствии исходного значения берётся из `facility_type`. Покрытие каждой ВПП находится в `runways[].surface`, а `runway_surfaces` выводит эти значения отдельным списком для удобства просмотра CSV. Исходные обозначения покрытий сохраняются. Набор сбора ограничен объектами с валидным четырёхбуквенным ICAO; это не все объекты OurAirports.

Форматы можно выбрать и без правки конфигурации: `python .\sort_airports.py --formats json ndjson`. Выходные файлы находятся в `outputs/selected/airports.*`. При повторном запуске создаются новые файлы, а файлы невыбранных форматов из этой папки удаляются. Для MongoDB используйте `airports.ndjson`; каждый аэропорт записан на отдельной строке с полем `_id`.

Зависимости: `pip install -r requirements.txt`. Проверка: `.\.venv\Scripts\python.exe -m unittest discover -s tests`.
## Дополнение по September.pdf — 5 октября 2026

Для сдачи запускайте `python assignment.py` из этой папки. Результат: `outputs/assignment/airports.csv` и `airports.json`. Все четыре формата: `python assignment.py --formats csv json toml yaml`.

Добавлены `status` (`open`/`close`) и IANA `timezone`. Статус получен из типа OurAirports; это классификация справочника, а не независимая проверка эксплуатации. Часовой пояс вычислен по координатам библиотекой timezonefinder. Поле `runways` сохраняет название, длину в футах и покрытие каждой ВПП.

По уточнению задания выгрузка включает только объекты с валидным четырёхбуквенным ICAO, включая закрытые. Объекты без ICAO исключаются при каждом запуске assignment.py. Другие отсутствующие данные и маршруты не исключают строки. Отсутствующий ICAO не заменяется локальным кодом. Пробелы исходных данных перечислены в `missing_source_fields.csv`, статистика — в `summary.json`. TOML не поддерживает null, поэтому отсутствующие значения в этом формате представлены отсутствием ключа.

Основной HTML-парсер также сохраняет новые поля. `python sort_airports.py` обновляет существующую выборку в `outputs/selected`; её охват остаётся ограничен исходным HTML-обходом по ICAO. Зависимости новых форматов добавлены в `requirements.txt`.
